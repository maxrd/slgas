# SLGAS 整合優化計畫：設定流與能源感測器支援

本文件紀錄了針對 SLGAS 瓦斯自動回報整合的優化需求與實施方案。

---

## 1. Config Flow 邏輯優化 (分段式設定)

### 現狀問題
目前所有設定欄位皆在同一頁面顯示，且無法針對「Google AI」與「外部實體」兩種模式進行欄位必填驗證。

### 優化方案
將 `ConfigFlow` 與 `OptionsFlow` 同步修改為分段式 (Two-step process)：

#### 第一階段 (User Step)
- 填寫基本資料：用戶編號、姓名、手機。
- 選擇度數來源 (`ocr_source`)。

#### 第二階段 (Setup Step)
根據第一階段選擇的來源，動態顯示不同的欄位：

| 欄位 | Google AI 模式 | 外部實體模式 |
|---|---|---|
| `camera_entity` (攝影機) | ✅ 必填 | ❌ 不顯示 |
| `prompt` (AI 辨識指令) | ✅ 必填 | ❌ 不顯示 |
| `degree_entity` (度數來源實體) | ❌ 不顯示 | ✅ 必填 |
| `text_entity` (度數存放實體) | ✅ 必填 | ✅ 必填 |
| `schedule_time` (排程時間) | ✅ 必填 | ✅ 必填 |
| `notify_script` (通知腳本) | 選填 | 選填 |
| `history_days` (歷史紀錄天數) | 選填 | 選填 |

#### 驗證機制
- 在 `async_step_setup` 中加入驗證邏輯，若必填欄位缺失則返回錯誤提示。
- Google AI 模式：未填 `camera_entity` 時顯示錯誤。
- 外部實體模式：未填 `degree_entity` 時顯示錯誤。

#### OptionsFlow 同步分段
現有的 `SlgasOptionsFlowHandler`（修改設定）也是單頁面，需同步改為分段式，保持與 ConfigFlow 行為一致。

## 2. 能源感測器支援 (Energy Dashboard Support)

### 現狀問題
目前辨識出的度數存放於 `input_text`，該實體類型不具備 `device_class: gas` 等能源面板所需的 Metadata，無法直接用於 Home Assistant 的能源儀表板。

### 優化方案
新增一個原生的度數感測器 (`SlgasMeterSensor`)，由整合自動建立，**與現有的 `SlgasReportSensor`（狀態感測器）並存**。

#### 感測器架構

| 感測器 | 類型 | 用途 |
|---|---|---|
| `SlgasReportSensor` (現有) | 文字狀態 | 顯示「上報成功」、「辨識完成」等流程狀態 |
| `SlgasMeterSensor` (新增) | 數值型 | 儲存瓦斯度數，支援能源面板 |

#### `SlgasMeterSensor` 規格
- **名稱**: `瓦斯度數 ({cus_no})`
- **Unique ID**: `{entry_id}_meter`
- **Device Class**: `gas` (將感測器類別定義為瓦斯)
- **State Class**: `total_increasing` (累進總量，讓 HA 能計算兩次讀數間的消耗差值)
- **Unit of Measurement**: `m³` (立方公尺，即台灣瓦斯計費的「度」)
- **Icon**: `mdi:counter`
- **混入類別**: `RestoreEntity` (確保 HA 重啟後能自動恢復上次的度數值)

#### 能源計算原理說明
Home Assistant 的「能源」面板支援 `kWh` 以外的多種能源類型。對於瓦斯數據，標準做法是使用 `m³` 作為單位。
- **單位對應**: 台灣瓦斯的「一度」等同於 1 立方公尺 (`m³`)。
- **消耗計算**: 透過設定 `state_class: total_increasing`，能源面板會自動記錄歷史數值。當度數從 `100` 變為 `105` 時，系統會自動判定這段期間消耗了 `5 m³` 的瓦斯，並顯示於日、週、月報表中。
- **直接整合**: 此感測器不需經過任何轉換，即可直接加入能源面板的「瓦斯消耗」設定中。

#### 重啟資料保留 (RestoreEntity)
使用 `RestoreEntity` 混入類別，確保 HA 重啟後感測器能自動恢復上次的度數值。這對 `total_increasing` 類型尤其重要，若重啟後數值變成 `unknown`，會導致能源面板資料斷裂、出現異常的消耗量計算。

實作方式：
```python
from homeassistant.helpers.restore_state import RestoreEntity

class SlgasMeterSensor(SensorEntity, RestoreEntity):
    async def async_added_to_hass(self):
        """Restore last known state on startup."""
        await super().async_added_to_hass()
        last_state = await self.async_get_last_state()
        if last_state and last_state.state not in ("unknown", "unavailable"):
            self._attr_native_value = int(last_state.state)
```

#### 運作邏輯
- 每當執行 `execute_full_workflow` 成功辨識或讀取到度數時，**優先更新原生 `SlgasMeterSensor`**。
- 若使用者有額外設定 `text_entity` (input_text)，則同步更新（作為備用）。
- 由於具備正確的 `state_class` 與 `device_class`，此感測器將可直接在 HA 能源面板中選取使用。

## 3. `text_entity` 角色調整

### 現狀問題
原本 `text_entity` (input_text) 是存放度數的唯一位置，且為必填欄位。但在新增原生能源感測器後，兩個地方存放相同的度數會造成混亂。

### 優化方案
- 將 `text_entity` 從 **必填** 改為 **選填**。
- 整合本身的 `SlgasMeterSensor` 作為度數的主要儲存位置。
- `text_entity` 保留為備用選項，供使用者在自動化或通知中引用。
