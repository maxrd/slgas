# 欣隆天然瓦斯自執度數 (HACS 專案) 完整需求與技術分析報告

本文件結合了 `docs/readme.md` 的專案需求以及對欣林瓦斯 (slgas.com.tw) 網站的技術分析，作為開發 HACS 自定義組件的實作指南。

## 一、 專案目標
開發一個 Home Assistant 自定義組件，實現自動化的天然瓦斯度數報表。系統需具備定時拍照、AI 辨識度數、自動提交至瓦斯公司網站、以及保留歷史紀錄的功能。

## 二、 核心需求 (依據 readme.md)

### 1. 用戶自訂配置 (Config Flow)
在 HACS 整合設定介面中，使用者需能輸入以下資訊：
* **用戶編號 (`CusNo`)**: 例如 ``
* **用戶名稱 (`CusName`)**: 例如 ``
* **用戶手機 (`Cuscallno`)**: 例如 ``
* **攝影機選擇**: 讓使用者從 HA 現有攝影機實體中選擇一個，紀錄其 `entity_id`。
* **度數存放實體**: 讓使用者選擇一個 `input_text` 實體，用來存放 OCR 辨識後的度數，紀錄其 `entity_id`。
* **定時排程時間**: 使用者自訂每日執行的「時、分」。

### 2. 自動化執行流程 (Workflow)
當設定的排程時間到達時，系統自動執行：
1. **拍照**：呼叫選定的攝影機進行拍照，存檔為 `gas.jpg`。
2. **AI OCR 辨識**：呼叫 Google AI OCR Action 讀取 `gas.jpg`，辨識出瓦斯表度數。
3. **數值存放**：將辨識結果寫入選定的 `input_text` 實體。
4. **網站報表**：執行兩道式 HTTP POST 流程（詳見下述技術分析）將度數送出。
5. **狀態更新**：將執行結果（日期、度數、成功/失敗）紀錄在 `sensor.slgas_last_report` 的擴展屬性中。

### 3. 手動觸發功能
在 HA 介面上提供一個按鈕，讓使用者隨時點擊執行上述完整流程。

### 4. 歷史紀錄
* 系統需保留最近 **2 個月** 的執行紀錄，方便使用者在 HACS 整合介面或感測器中查看。

## 三、 技術分析：兩道式 HTTP 報表流程

經過分析，欣隆 (欣林) 瓦斯網站 (`https://www.slgas.com.tw/`) 採用兩段式提交機制，必須保持 Session Cookie 狀態。

### 第一道關卡：身分驗證
* **網址**：`https://www.slgas.com.tw/GetDegree_SQL.asp` (或由 `Report_SQL.asp` POST 提交)
* **方法**：`POST`
* **參數 (Payload)**：
  * `CusNo`: 用戶編號
  * `CusName`: 用戶名稱 (須以 Big5 編碼)
  * `Cuscallno`: 用戶手機
  * **`ChkField`**: `Check` (隱藏欄位，用於身分驗證)
  * `Send`: `送出` (Submit 按鈕名稱)

### 第二道關卡：度數提交
在第一步成功後，必須維持同一個 Session，並對同一個網址發送第二次 POST。
* **網址**：`https://www.slgas.com.tw/GetDegree_SQL.asp`
* **方法**：`POST`
* **參數 (Payload)**：
  除了新的度數外，必須包含從第一步 HTML 中提取出的預設值：
  * `CusTel`: (自動提取)
  * `CusEMail`: (自動提取，例如 `maxrd@gmail.com`)
  * `cus_sDegree`: (自動提取，上次度數)
  * `cus_sLOG_DAY`: (自動提取)
  * `cus_sLOG_DEG0`: (自動提取)
  * **`CusDegree`**: 我們要報表的瓦斯度數 (例如 `131`)
  * **`ChkField`**: `Append` (關鍵隱藏欄位，用於資料寫入)
  * `send`: `送出` (Submit 按鈕名稱)

### 成功判定標準
回傳的 HTML 中若包含以下字串，則視為成功：
`瓦斯錶度數已登錄完成，謝謝您！`

## 四、 實作計畫 (Implementation Details)
1. **設定檔管理**：使用 `config_flow.py` 處理用戶輸入。
2. **通訊處理**：利用 `aiohttp.ClientSession` 自動管理 Cookie 與兩次 POST。
3. **資料解析**：使用 `re` 或 `BeautifulSoup` 提取第二步所需的隱藏欄位值，並驗證成功字串。
4. **感測器屬性**：在 `sensor.py` 中維護 `history` 列表，限制長度為 60 (約兩個月)。
